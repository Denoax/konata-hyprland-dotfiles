# Kona event/state contract — Task 01

Implementation: Hyprland 0.56.2 native Lua in `.config/hypr/hyprland.lua`.
No resident event listener or state daemon. Direct Hyprland remains canonical.

## Owners and interfaces

| State | Authoritative owner/path | Read/transition interface |
|---|---|---|
| Restorable apps | `kona-session-save`; `$XDG_STATE_HOME/kona/session.json` | Existing save/restore/toggle commands; unchanged array format and class deduplication |
| Restore preference | `$XDG_STATE_HOME/kona/session-restore-enabled` | Existing toggle; startup initialization retains prior enable behavior |
| Workspace thumbnails | `kona-workspace-capture`; `$XDG_RUNTIME_DIR/kona-overview/workspace-N.png` | Worker `1..10` refreshes a currently visible workspace; `--visible` refreshes current outputs on demand |
| Gaming | `kona-game-mode`; `$XDG_RUNTIME_DIR/kona-game-mode` | `on/off/toggle/status/waybar`; `reconcile` reapplies existing intent after reload |
| Recording | `kona-record`; `$XDG_RUNTIME_DIR/kona-record/` | Existing `region/output` toggle; `kona-record-status` JSON |
| Wallpaper mode | Existing `kona-wallpaper`; `$XDG_STATE_HOME/kona-wallpaper-mode` | Existing `status` and mode actions |
| Night-light override | Existing `kona-night-light`; `$XDG_STATE_HOME/kona/night-light-manual` | Marker means manual override intent, not actual current scheduled temperature; reset at startup |

`kona-state [status]` produces a read-only schema-1 aggregation of gaming,
recording, wallpaper mode and night-light mode. It does not create a second store,
mutate owners, invent profiles/scenes, or promise an atomic transaction across
independent owners. Readers tolerate absent state. Existing compatibility files
stay valid. New JSON output is generated by jq; the legacy session array remains
unversioned deliberately so existing restore files keep working.

## Scheduling and synchronization

Window open/close, workspace movement, fullscreen and detected floating changes
arm session persistence and affected-workspace captures. Captures debounce1.2s
per workspace; saves debounce1.5s after an initial30s startup grace. The serializer
uses a shared lock, unique temporary file and rename; unchanged bytes retain the
existing inode/mtime. Restore holds that lock while consuming its startup snapshot
and releases it before a final save. Manual save uses the same path.

There is no native geometry/minimize event in the installed ABI. Kona minimize
uses a special-workspace move and retains the existing restore-to-workspace2
fallback. Non-consuming mouse press/release geometry checks cover existing drags
and border resizing; focus transitions conservatively schedule a save for external
geometry operations. Unannounced geometry changes to an inactive window can wait
until the next meaningful event or manual save. No geometry polling timer exists.

History workers serialize with the overview, use unique PNG temporaries, and
check the output/workspace mapping before and after capture. Failed captures or
output disappearance retain the last complete image. The overview prevents
background capture of its own surface and retains its ten-card Rofi menu, app
counts, icon fallback and full-resolution PNG quality. Gaming suppresses background
capture; an explicit overview request can still refresh. Hidden thumbnails retain
the last completed meaningful view; there is no claim of pre-switch capture or
perfect detection of an output switching away and back during one capture.

One-shot timers are recreated after firing. Hyprland cancels timers and removes
subscriptions on reload. The verifier also emits `config.reloaded`; the callback
must skip live work when no monitors exist. Shutdown requests a best-effort async
save; if IPC has gone away, the previous valid snapshot survives. A guaranteed
pre-exit snapshot requires a separate pre-exit contract; the uncertain session-menu
script is outside this task.

The old `kona-session-daemon` and `kona-workspace-history-daemon` names remain
one-shot compatibility entry points. Neither runs a loop or stays resident.

## Waybar and recording

`kona-waybar-refresh recording|gaming` owns reserved RTMIN offsets8/9, matching
Waybar's `signal` fields. It targets exact-name Waybar processes of the same UID;
absence is normal. Both modules execute at startup and after producer signals,
with no `interval` or speculative click refresh. GPU5s, CPU/RAM3s and clock1s
remain unchanged. Ordinary state changes never restart Waybar.

Recording publishes PID last under its lock and includes process start ticks to
avoid PID reuse. Legacy active recordings without that field are accepted only
for an actual wf-recorder process. A recording-scoped child waits for recorder
exit and clears state/signals on unexpected exit. It exits when recording ends;
there is no idle supervisor. Bounded startup/stop waits are action-time checks.
A failed stop retains active state instead of reporting a false successful stop.

The strict transition-only default uses `● REC` while recording; a ticking elapsed
clock would require active periodic refresh. CSS classes, JSON schema, click action
and idle appearance are unchanged. This explicit tradeoff was raised with the user;
subjective acceptance of this sole visible difference remains for review.

## Validation

- `python3 tests/event-state.py`: real shell/files/flock, controlled external IPC,
  capture failures, locking, state/legacy interfaces and recorder lifecycle.
- `lua tests/event-state.lua .config/hypr/hyprland.lua`: actual callback bodies with
  deterministic one-shot time; burst coalescing, focus filtering, geometry and idle.
- `tests/recovery-smoke.sh`: isolated-home install and native config verification.

Live behavior, screenshots and matched CPU/PSS/cadence evidence live in the Task01
evidence directory linked by `PROJECT_HANDOFF.md`; offline tests alone do not prove
rendering or performance.
